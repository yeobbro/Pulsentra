- **분할 비율**(공시서류원본파일 `document.xml`, 요청 2회·재시도 0): 원 공시 원문에서 1주당 가액 5,000원→100원, 보통주 128,386,494주→6,419,324,700주, 우선주 18,072,580주→903,629,000주로 **모두 정확히 50배**입니다. 감사가 추정한 50:1과 일치합니다. 원 공시의 신주권 상장예정일은 2018-05-16이었고, 후보 날짜(2018-05-04, 네이버 일봉의 거래 재개일)와 다릅니다.
- **정정 공시 원문은 받지 못했습니다**: `document.xml`이 상태 `014`(파일이 존재하지 않습니다)를 돌려줬습니다. 그래서 정정 내용(예: 일정 변경)은 확인하지 못했습니다. 두 공시가 같은 기업행동이라는 판단의 근거는 공식 정의상 `[기재정정]`이 "이미 제출된 같은 보고서명의 보고서"를 뜻한다는 점, 같은 회사·같은 보고서명, 그 사이에 다른 분할 공시가 없다는 점입니다. 내용 대조로 확인한 것은 아닙니다.

## KRX Open API (v0.4, `app/providers/krx.py`, `python -m app.krxcheck`)

| 서비스 | 경로(실서비스) | 내용 |
|---|---|---|
| KOSPI 시리즈 일별시세정보 | `/svc/apis/idx/kospi_dd_trd` | 기준일 하루의 KOSPI 계열 지수 전부 (종가·시가·고가·저가·거래량·거래대금·시총) |
| KOSDAQ 시리즈 일별시세정보 | `/svc/apis/idx/kosdaq_dd_trd` | 같은 형식, KOSDAQ 계열 |
| 유가증권 일별매매정보 | `/svc/apis/sto/stk_bydd_trd` | 기준일 하루의 유가증권 전 종목 OHLCV·거래대금·시총·상장주식수 |
| 코스닥 일별매매정보 | `/svc/apis/sto/ksq_bydd_trd` | 같은 형식, 코스닥 |

- 호스트 `https://data-dbg.krx.co.kr`, GET, 파라미터 `basDd=YYYYMMDD`, 인증 헤더 `AUTH_KEY`. 응답 `{"OutBlock_1": [...]}`, 값은 모두 문자열.
- 샘플 전용 경로 `/svc/sample/apis/...`(공개 샘플 키, 고정 날짜)는 쓰지 않습니다. 실서비스 키로 샘플 경로를 부르면 HTTP 403이 납니다.
- **명세 확인 상태 (2026-10-24 갱신):** 처음에는 `openapi.krx.co.kr`에 접근할 수 없어 공개 클라이언트 패키지 두 개(krx-openapi 0.2.2, pykrx-openapi 0.1.1)로 교차 확인했습니다. 2026-10-24에 사용자 컴퓨터에서 공식 서비스 상세 페이지(로그인 없이 공개, 최근 수정일 2026/01/16)를 열람했습니다. 페이지에 들어 있는 서비스 정의(BLD)로 위 4개 서비스의 **경로, `AUTH_KEY` 헤더, `basDd` 입력, 출력 필드와 순서가 코드와 일치**함을 확인했습니다. 원문 사본은 `data/krxcheck/official_spec_20261024/`(Git 제외)에 있습니다. 공식 페이지에는 오류 코드·HTTP 상태 설명이 없으므로, 오류 처리는 여전히 관찰과 공개 패키지 기준입니다. `--spec-confirmed`는 실행하는 사람이 자기 승인 서비스를 확인했다는 표시로 계속 요구합니다.
- **공식 정의에서 확인한 조회 조건:** `stk_bydd_trd`는 `MKT_ID='STK'`, 증권그룹 `ST, DR, MF, RT, SC, IF, FS`를 포함합니다. 그래서 우선주·리츠·펀드 등도 들어 있고, 보통주만 수집한 로컬 유니버스에 없는 행이 생깁니다. 행은 `AGG_BAS_TP_CD='0'` 조건으로 고릅니다(코드의 뜻은 페이지에 설명 없음, 미확인). 기준일은 오늘보다 과거여야 하고, 가장 최근 거래일은 **다음 날 08시 이후**에만 조회됩니다.
- **가격 기준(실호출로 확인):** 공식 정의는 일별 체결가 테이블(`TBMD_BYDD_ISU_TRDPRC`)의 `TDD_*` 값을 그대로 돌려줍니다. 2025-02-27·2025-06-12 전체 시장 대조에서 네이버와 다른 행은 모두 OHLC가 같은 비율로 다른 `adjusted_price_basis`였습니다. 즉 KRX는 수정 전 실제 가격, 네이버는 수정주가입니다.
- **종목코드 형식(확인):** 공식 정의는 `SUBSTR(ISU_SRT_CD, 2)`, 즉 6자리 단축코드입니다. 실호출 4회에서도 모두 단축코드였습니다(`isu_cd_forms_seen: ["short"]`). 코드는 계속 두 형식을 모두 받습니다.
- **오류(공개 패키지 기준, 공식 문서 없음):** 실패도 HTTP 200에 `respCode`/`respMsg`로 올 수 있습니다(`401` = 키 오류 또는 서비스 미승인). HTTP 403은 잘못된 키·URL, 429는 호출 한도입니다. **호출 한도는 이용약관에서 확인**: 키당 하루(0~24시) 10,000회 이하, 초과 시 서비스가 중지될 수 있습니다. 12개월 미사용 키는 삭제될 수 있습니다.

#### 현재 KRX 연동의 사용 가능 범위

| 용도 | 현재 판단 |
|---|---|
| 본인 연구용 로컬 검증(`app.krxcheck`, `data/krxcheck/`, Git 제외) | 약관 범위 안으로 보임(비상업적·제3자 미제공). 키 유효기간 안에서만 |
| 앱 저장소(`candles`) 적재·화면 표시 | **코드로 차단**(`app/data/schema.py`의 `license_refusal`): ① `ingest_frame`의 출처 인자, ② 넘겨받은 표의 `source` 열(CSV 업로드가 `csv_import`로 바꿔 쓰기 전), ③ 실제 쓰기 함수 `db.upsert_candles`. 대소문자·앞뒤 공백은 무시합니다. 거부는 적재 기록을 포함해 아무것도 쓰기 전에 일어납니다 |
| 외부 사용자에게 시세·파생지표 표시, 다운로드, API 제공 | **불가** — 제11조②. 코스콤 일반 이용계약 등 별도 계약 필요(문서상) |
| 유료 서비스·수익 사업 | **불가** — 제6조②. 별도 계약 필요 |
| KRX 데이터로 만든 지수·지표 공표 | 지수산출목적 이용계약 필요 여부 확인 필요 |

## 데이터 처리 규칙 (리서치 로더 `app/research/data.py`)
1. **거래 정지 표시 행**(시가=고가=저가=0): 일봉이 아니므로 제거하고 `provider_halt_rows.csv`에 기록합니다.
2. **수정주가 반올림 오차**: 종가가 고가보다 1원 큰 것처럼 상대 0.2% 이내로 어긋난 행은 고가·저가를 넓혀 보정합니다. 보정한 행에는 `ohlc_rounding_repaired` 플래그를 남깁니다. 그보다 크게 어긋나면 오류로 제외합니다.
3. **거래량 미수정 분할·병합**: 거래 정지 공백을 사이에 두고 60거래일 중앙 거래량이 3배 이상 변하면 `volume_level_break`로 표시합니다. 그 지점을 포함하는 40거래일 거래량 창의 신호는 모든 전략에서 제외합니다(무작위 기준 포함).
4. **거래대금**: `수정종가 × 거래량`으로 추정합니다. 유동성 필터에만 쓰며, 분할 전 구간에서는 실제보다 작게 추정됩니다(보수적).
5. **현금 배당**: 반영하지 않습니다. 모든 수익률은 배당을 뺀 가격 수익률입니다.
6. **탐지하지 못하는 것**: 거래 정지 없이 일어난 무상증자 등의 거래량 불연속.
