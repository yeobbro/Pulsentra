# Pulsentra v0.4 — 데이터 감사·재현성·교차 검증 기반 (진행 중)

작성 2026-10-23. v0.3 결론(`docs/RESEARCH_V0_3.md`)은 바꾸지 않았습니다. 이 문서는 v0.4에서 새로 만든 것과 확인한 것, 그리고 아직 확인하지 못한 것을 구분해서 적습니다.

**요약:** v0.4는 새 전략을 찾는 단계가 아닙니다. v0.3 결과를 믿을 수 있는지 판단하는 데 필요한 도구를 만든 단계입니다.

- 만든 것: 종목 단위 데이터 감사, 재현 가능한 실행 기록, 공식 출처 교차 검증 도구, 결과 상태 판정
- 실행하지 못한 것: 이 개발 환경에는 실제 데이터(`data/real/`)와 API 키가 없어서, 실제 데이터 감사와 교차 검증은 실행하지 못했습니다.
- 따라서 v0.3 수치를 다시 계산하지 않았고, 새로운 전략 성과도 없습니다.

## 3. 발견한 문제와 처리

| 문제 | 영향 | 처리 |
|---|---|---|
| `pd.Timedelta(days=…)`, `resample`, 시간 단위가 다른 datetime `concat`이 NumPy 2.5에서 DeprecationWarning을 냄(173건) | NumPy가 이를 오류로 바꾸면 리서치 실행이 중단될 수 있음 | 원인 코드를 고침. 결과 동일성 확인. CI가 경고를 오류로 처리 |
| 원본 파일에 숫자가 아닌 셀이 하나만 있어도 `load_naver_raw`가 `TypeError`로 중단 | 수천 종목 실행 전체가 한 셀 때문에 실패 | 값과 날짜를 강제 변환하고, 깨진 행은 기록 후 제거. 회귀 테스트 추가 |
| 주말 날짜 행을 로더가 그대로 사용 | 존재할 수 없는 봉이 신호와 체결에 쓰일 수 있음 | 감사가 오류로 보고. `--audit` 사용 시 주변 신호 제외. 로더 동작은 기준선 유지를 위해 그대로 둠 |
| 신호 단위 시뮬레이터가 청산 전에 데이터가 끝난 거래를 제외 | 상장폐지 직전 손실 거래가 빠져 거래 단위 평균이 위로 치우칠 수 있음 | 실행마다 그 수를 기록(`incomplete_trades_dropped`). 계산 방식 변경은 v0.3 비교성을 해치므로 보류 |
| 일부 거래가 신호 기간 끝을 넘어 청산될 수 있음(공휴일·거래정지) | 다음 기간의 가격이 이전 기간 성과에 섞임 | 거래별로 표시하고 기간별 수를 기록. embargo가 너무 짧은 설정은 거부 |
| 교차 검증 결과가 결과 상태 판정에 연결되지 않음 | 검증해도 보고서에 반영되지 않음 | `--crosscheck`로 연결. 통과한 검증만 인정 |

## 4. v0.3 결론과의 비교

| v0.3 결론 | v0.4 상태 |
|---|---|
| 비용 차감 후 validation·test 양쪽에서 우위가 있는 조합 없음(480개 중 0개) | **변경 없음.** 실제 데이터로 다시 실행하지 않음. 데이터 감사 결과가 이 결론을 바꿀지는 미확인 |
| A는 dev에서만 우위(과적합) | 변경 없음 |
| ML 15개 모두 불채택 | 변경 없음. ML은 실험 모듈로 유지 |
| 가격 단일 출처, 기업행동 미대조, 배당 미반영 | 대조 **도구**는 만들었지만 **실행하지 않음**. 배당은 여전히 미처리 |

v0.4 코드로 다시 실행하면 결과 상태는 최소 PROVISIONAL입니다. 배당, 무정지 무상증자 같은 미처리 항목이 남아 있기 때문입니다. 상장폐지 종목 데이터가 없는 표본은 INELIGIBLE입니다. 이 상태에서는 전략을 채택할 근거가 없다는 v0.3 판단을 유지합니다.

## 5. 남은 작업 (우선순위)

1. **실제 데이터 감사**(데이터가 있는 환경): `python -m app.audit --data data/real`. v0.3 품질 수치가 재현되는지, `non_positive_price`가 몰린 종목의 원인이 무엇인지 확인합니다.
2. **KIS 교차 검증**(키 필요): 감사 후보 절반과 무작위 절반으로 30종목을 표본 대조합니다. `acml_vol`이 수정되는지, `prtt_rate`·`mod_yn` 값이 무엇을 뜻하는지 확인합니다.
3. **OpenDART 공시 매칭**(키 필요): 분할·병합·무상증자 후보를 확인하고, 놓친 이벤트(`undetected_event`)가 얼마나 되는지 셉니다.
4. 1~3 결과에 따라 감사 임계값과 로더 규칙을 조정합니다(주말 행 제거 등). 조정은 새 버전으로 기록합니다.
5. **감사 반영 재실행:** `--audit --crosscheck`로 v0.3 설정을 그대로 다시 돌리고 v0.3 수치와 비교합니다. test 기간은 이미 한 번 썼으므로 선택에 쓰지 않습니다.
6. 배당·총수익 지수, 연도별 세율 일정, 상장폐지 목록 참조(KRX KIND) 확보.
7. 그 다음에야 새 가설을 사전 등록 방식으로 검증합니다. 2026-11 이후 데이터를 새 test 기간으로 남겨 둡니다.
